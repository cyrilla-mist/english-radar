# English Radar v1.2：Learn Through the Interface

## 1. V1.2 产品目标

V1.2 的主题是 **Learn Through the Interface**：让 English Radar 自己的界面成为 UI Vocabulary 的真实学习材料。用户可以在主动开启的 Interface Learning Mode（界面学习模式）中，点击少量预先标记的界面词，查看它在产品语境中的含义、使用边界和相关表达，并进入完整 Signal 学习页。

本阶段保持 English Radar 的 local-first、无框架、低干扰特征。普通浏览模式不自动扫描文字、不改变现有页面交互，也不要求用户学习全部界面文案。

## 2. 当前架构审计

### Today / Session

- `index.html` 提供 Daily Mix、Discovery、Review、Session 和 Category Focus 入口。
- `js/learning-engine.js` 从 `EnglishRadarContent.getActiveLearningSignals()` 获取基础词库，并结合 `js/storage.js` 的 progress 构建 Daily Mix、Unseen、topic/category 过滤结果和 Today snapshot。
- `js/app.js` 与 `js/dashboard.js` 读取同一份 Today snapshot，分别负责首页状态、统计和 Daily Mix 预览。
- Start 链接通过 `size`、`feed`、`topic` 等相对 URL 参数进入 `learn.html`；`js/session.js` 决定 session 模式和数量，并保持确定性排序与复习状态兼容。

### Learn

- `learn.html` 已有 Meaning、Context、Signal Profile、Usage Boundary、Chinese Feeling 和 mastery 章节。
- `js/session.js` 直接从 Signal 对象读取 `meaningEn/meaningZh`、`exampleEn/exampleZh`、`useWhen`、`avoidWhen`、`platforms`、`tone`、`status`、`formality` 等字段。
- 当前没有按 Radar Type 切换模板；缺少可选字段时使用既有安全回退。因此 V1.2 应先增加可选模板分支，不应替换现有 Signal Profile。

### Dictionary

- `dictionary.html` 与 `js/dictionary.js` 目前按 Community、Mastery、Favorites、Personal 等视图工作。
- 筛选使用现有 `signal.category`、source、mastery 和 favorite 数据；当前没有 `radarType` 层。
- 建议把 `radarType` 作为正交语义维度：保留旧 Category 筛选，同时允许 `radarType: "interface"` 提供 UI Vocabulary 视图或筛选，不把旧分类迁移为新分类。

### Quiz

- `data/quizzes.js` 保存 120 个 Core Quiz；每题通过 `signalId` 关联 Signal。
- `js/quiz.js` 兼容旧 `type` 字段，并规范化为 `meaning`、`context`、`boundary` 题型及 easy/medium/hard 难度。
- `js/imported-quiz-generator.js` 为字段完整的 Imported Signal 按需生成动态题目。V1.2 可新增 `interface-context` 的表现层题型，但应沿用现有 Quiz 关联、历史和错题机制，不改写旧题。

### Review / Session / Storage

- `js/storage.js` 将 progress 按 Signal ID 保存；记录包含 mastery、review 时间、reviewCount、errorCount 和 favorite。
- current session 保存 signal IDs、当前位置和 masteryResults；quizHistory 保存 byQuiz 与 attempts。
- `js/review.js` 按 Signal ID 计算 New/Fuzzy/Clear 的复习间隔。新的 UI Signal 只要使用稳定 ID，就能自动复用学习、复习和掌握状态，不需要迁移或重置 LocalStorage。

### UI Copy 与数据管线

- `js/ui-copy.js` 集中处理导航、区块、操作标签和中英文辅助文案，并增强 Me 折叠区摘要。
- `data/signals.js` 当前为 60 个 Core Signals，`data/quizzes.js` 当前为 120 个 Core Quizzes；`scripts/validate-data.js` 对这些 Core 数量有明确校验。
- `js/content-registry.js` 会保留 Signal 中的未知/可选字段，同时只要求现有必填字段；这为新增 UI Vocabulary 元数据提供了向后兼容基础。
- Content Pack 使用 `English Radar Content Pack` schemaVersion 1，Notion 导入经 Worker 和现有 Registry 处理。V1.2 不修改 Worker、现有 Signal ID 或 Content Pack 必填字段。

### 测试基线

现有覆盖包括：

- `scripts/validate-data.js`、`scripts/check-project.js`
- `tests/learning-engine-v1.1.test.js`
- `tests/quiz-engine-v1.1.test.js`
- `tests/performance-v1.1.test.js`
- `tests/v1.1.1-bilingual.test.js`
- `worker/test/signal-id.test.js`

V1.2 应在现有测试不变的基础上增加 schema、目标绑定、模式开关、面板可访问性和移动端布局测试。

## 3. 建议数据模型（向后兼容）

不新增必填字段，不修改现有 60 个 Core Signal，不改变 Signal ID。建议把以下字段作为可选 Signal 元数据：

```js
{
  radarType: "interface",
  uiArea: ["today", "learn", "quiz", "dictionary", "review"],
  originalMeaningEn: "...",
  originalMeaningZh: "...",
  productMeaningEn: "...",
  productMeaningZh: "...",
  whyProductsUseItEn: "...",
  whyProductsUseItZh: "...",
  commonInterfaces: ["..."],
  realInterfaceExamples: ["..."],
  relatedTerms: ["ui-signal"],
  confusedWith: ["..."],
  interfaceTargets: ["today.daily-mix.title"],
  usageBoundaryEn: "...",
  usageBoundaryZh: "..."
}
```

设计约束：

- `radarType` 建议初始枚举为 `internet`、`interface`，缺失时按现有 Signal 行为处理。
- `uiArea`、`commonInterfaces`、`realInterfaceExamples`、`relatedTerms`、`confusedWith`、`interfaceTargets` 为字符串数组；内部关联优先使用稳定 Signal ID。
- `interfaceTargets` 使用语义 target key，不使用脆弱的 CSS selector。
- `originalMeaning*` 表示一般英语含义，`productMeaning*` 表示在产品界面中的含义；两者都缺失时继续使用现有 meaning 字段。
- Content Registry 继续以现有字段校验 Signal；存在新字段时只做类型和枚举校验。
- UI Vocabulary 可以来自独立静态 registry，也可以来自 Content Pack；若进入现有 Pack，新增字段必须保持可选，不能让旧导入包失效。
- 首批 UI Signal ID 使用 `ui-` 前缀，例如 `ui-daily-mix`，符合当前 ID 规则且不与 Core/Imported ID 混淆。

为避免破坏 `validate-data.js` 的 60/120 Core 计数，Phase 1 应优先使用独立的 `data/ui-vocabulary.js` 或单独可验证的 Interface Pack；不要把规划中的 10 个词直接追加到 Core 数据文件。

## 4. Interface Learning Mode 技术方案

推荐采用 **集中 Registry + 显式 `data-ui-term` 标记** 的组合：

1. Registry 保存 UI Signal 的规范元数据、显示词、ID、出现页面和 target key。
2. 页面只在明确选定的元素上增加 `data-ui-term="ui-daily-mix"` 等标记。
3. 模式关闭时，标记元素保持普通文本或原有链接行为；不添加额外交互。
4. 模式开启时，仅标记元素获得可点击语义和键盘焦点；不扫描页面全文、不自动包裹文本、不误标普通英文。
5. 点击后打开轻量学习面板，显示英文/中文简释、UI area、产品语境、使用边界和相关词；提供 `Open full Signal`，通过现有 `learn.html?mode=lookup&signal=<id>` 进入完整学习页。
6. 面板使用原生 DOM/CSS，具备 `role="dialog"`、关闭按钮、Escape 关闭、焦点回收和足够的移动端点击区域。
7. 首版模式状态建议只保存在当前页面内存中，避免新增设置迁移；后续若需要跨页记忆，再以显式 Preferences 选项加入现有 settings。

不推荐运行时文本扫描：它会误标普通正文，受空格、大小写、翻译和 DOM 结构影响，且在移动端增加不必要的遍历与重排成本。

## 5. 首批 10 个 UI Vocabulary

| 词 | 稳定 Signal ID | 当前出现位置 |
|---|---|---|
| Daily Mix | `ui-daily-mix` | Today 的 Daily Mix 区块、Learn 入口 |
| Signal | `ui-signal` | Today 统计、Learn Signal 标题与进度 |
| Session | `ui-session` | Today 的 Library Session、Learn session 信息 |
| Inbox | `ui-inbox` | 主导航、Inbox 页面 |
| Dictionary | `ui-dictionary` | 主导航、Dictionary 页面 |
| Archive | `ui-archive` | Dictionary / Personal Archive 相关文案 |
| Sync | `ui-sync` | My Radar 的 Notion Sync 区块 |
| Profile | `ui-profile` | Learn 的 Signal Profile 区块 |
| Review | `ui-review` | 主导航、Review 模式与 Review queue |
| Quiz | `ui-quiz` | Quiz / Context Check 页面和 Practice 入口 |

页面覆盖建议：Today 先标记 Daily Mix、Signal、Session；Learn 标记 Signal、Session、Profile；Quiz 标记 Quiz；Dictionary 标记 Dictionary、Archive；Review 标记 Review；Inbox 和 Sync 作为导航与 My Radar 的真实延伸入口。`Preferences`、`Import`、`Export`、`Preview`、`Workspace` 暂列为下一批，不为凑数提前加入。

## 6. 页面改动范围

- `index.html`：加入模式入口和少量 Today target 标记；保持现有 Session、Daily Mix 和导航行为。
- `learn.html` / `js/session.js`：增加 UI Signal 的可选展示模板或字段回退；保留现有 Meaning、Context、Usage Boundary 和 mastery 流程。
- `quiz.html` / `js/quiz.js`：为 interface-context 题型预留规范化分支；旧题继续按当前题型工作。
- `dictionary.html` / `js/dictionary.js`：增加可选 Interface/ Radar Type 视图或筛选，保留 Category、Source、Mastery 和 Favorites。
- `review.html`（如现有 Review 路由仍由页面逻辑承载）/ `js/review.js`：复用现有 Signal ID 和复习计划，不单独建立 UI Vocabulary 进度系统。
- `me.html` / `js/me.js`：后续提供 Interface Learning Mode 开关或说明；不在本轮实施。
- `js/ui-copy.js`：只增加模式入口、面板按钮和必要双语文案，不让所有 UI 文案自动变成学习链接。
- 新增 registry/controller 文件和 CSS/测试文件应在后续 Phase 逐步加入，本轮仅保留方案。

## 7. 测试方案

后续实施按以下层次测试：

1. 数据：新字段缺失时旧 Signal、旧 Pack、旧 Quiz 和旧页面仍通过；枚举、数组和 ID 关联错误可被报告。
2. Registry：10 个 UI ID 唯一，`data-ui-term` 能解析到 registry，未知 ID 不阻塞页面。
3. 模式：关闭时无新增可点击目标；开启时只有显式标记元素可点；同一词在不同页面能解析到同一 Signal ID。
4. 面板：能打开、关闭、Escape 关闭、进入完整 Learn；不包含 Token、Notion 配置或用户正文。
5. 兼容：现有 progress、quizHistory、review queue、Content Pack import/export、Notion Sync 均保持原结构。
6. 视觉/移动端：360、390、430、1440 宽度无横向滚动，面板不遮挡底部双层 Dock，长中文可换行。
7. 回归：继续运行现有 validate、project check、learning、quiz、performance 和 bilingual 测试。

## 8. 向后兼容策略

- 现有 Signal ID、Core Signal 数量、Core Quiz 数量、Content Pack schemaVersion 1 和 LocalStorage key 不变。
- 所有 V1.2 字段均为可选；渲染优先使用新字段，缺失时回退到现有 meaning/example/profile 字段。
- Progress、Review 和 Quiz History 仍以 `signalId` 为唯一关联键，不重置、不迁移、不覆盖用户数据。
- Imported Signal 缺少 UI 字段时继续按普通 Signal 运行，不强制生成 UI Quiz。
- Notion Sync 和 Worker 不需要知道 Interface Learning Mode；UI metadata 可先由静态 registry 提供，后续再通过兼容的 Content Pack 字段扩展。
- 导入、删除、Backup Replace 和 Reset 的现有 Registry 缓存失效逻辑保持不变。

## 9. 风险与非目标

风险：

- UI 文案在页面间重复出现，若缺少稳定 target key，可能出现漏标或误标。
- `radarType` 与旧 `category` 混用会导致 Dictionary 过滤语义混乱，因此必须保持两个维度独立。
- UI Signal 若没有清晰的产品语境和边界，学习面板会退化为普通 tooltip。
- 过早将 UI Vocabulary 放入 Core 数据会破坏现有数量校验和用户统计。
- 面板、底部 Dock 和中文内容叠加时需要重点验证手机可用区域。

非目标：

- 不做全页英文自动识别或自动链接。
- 不做 AI 解释、开放式输入、语音题或外部依赖。
- 不重写 Learn、Quiz、Dictionary 的既有视觉体系。
- 不修改 Worker、Notion 数据结构、现有学习数据或用户 LocalStorage。
- 不在本轮新增完整内容，也不部署或合并分支。

## 10. 分阶段实施计划

### Phase 1：Schema + 10 个 UI Vocabulary 数据

建立独立 UI registry 或兼容的 Interface Pack，完成 10 个稳定 ID、字段校验、静态加载和旧字段回退测试。暂不改变 Core Signal/Quiz 统计。

### Phase 2：Learn 页面 UI Vocabulary 模板

在 Learn 中增加可选 `radarType === "interface"` 展示层，展示 original/product meaning、产品使用原因、interface examples 和边界；字段缺失时回退到现有模板。

### Phase 3：Interface Learning Mode

加入显式模式开关、`data-ui-term` target binding、移动优先轻量面板、完整 Learn 链接和无障碍交互。验证模式关闭时零新增交互。

### Phase 4：Today / Quiz / Dictionary / Review 接入

把首批 target 标记加入真实页面；增加可选 Interface/Radar Type 筛选和 interface-context Quiz 入口；复用现有 Session、Review、Mastery 和 Quiz History。

### Phase 5：手机端测试与发布

使用真实 Core、Imported 和混合数据验证 360/390/430/1440；运行全部自动测试，检查加载成本、底部 Dock 避让、键盘/触屏交互和文案可读性，完成发布说明后再决定是否合并或部署。
